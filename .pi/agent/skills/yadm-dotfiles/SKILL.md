# yadm dotfiles

Home-directory config files are tracked by **yadm**, backed by
`github.com/taiki-kuraishi/dotfiles`.

## Rules

- **Never use `git` for these files.** `git` in `$HOME` targets the wrong (or no)
  repo. Always use `yadm` for status / diff / add / commit / push / log.
- Only touch files that are already tracked unless the user asks to add new ones.
  Check with `yadm ls-files`.
- Commit messages: **English**, imperative, prefixed with a **gitmoji**, in the
  form `<emoji> <scope>: <summary>` (e.g. `✨ pi: add statusline extension`).
  Match the existing style — run `yadm log --oneline -20` first and mirror it.

## Where things live

| What | Path |
| --- | --- |
| the repo (bare) | `~/.local/share/yadm/repo.git` |
| yadm's own config | `~/.config/yadm/config` (absent = defaults) |
| encrypt globs | `~/.config/yadm/encrypt` |
| bootstrap script | `~/.config/yadm/bootstrap` |
| hooks | `~/.config/yadm/hooks/` |

A `pre_commit` hook reformats staged files before the commit lands: `.nix` via
nixfmt, `.json` / `.yml` / `.yaml` via dprint, then re-stages them. Expect those
files to differ from what you wrote — that is the hook, not a mistake.

**`yadm config` and `yadm gitconfig` are different commands:**

- `yadm config <name> <value>` — yadm's own settings (`local.class`, `yadm.*`).
- `yadm gitconfig <name> <value>` — the **git** config of yadm's repo, e.g.
  `pull.rebase`, `user.signingkey`. This is what you want when changing how the
  repo itself behaves.

Plain `git config` in `$HOME` edits the wrong repo, exactly like plain
`git status` does.

## Finding a tracked file

Do not guess paths, and do not ask the user. Ask the repo:

```bash
yadm ls-files | grep -i <tool>
```

Three things the path alone will not tell you:

- **OS alternates.** `.config/yadm/bootstrap##os.Darwin` and `##os.Linux` are the
  real files; the plain `bootstrap` next to them is a symlink generated by
  `yadm alt` and is not tracked. Edit the `##`-suffixed file, then run `yadm alt`.
- **`.gitconfig` pulls in `.gitconfig-work`** through an `includeIf` scoped to
  work-org paths. Personal and work identity, signing keys, and credential
  helpers live in different files — check which one applies before editing.
- **sops + age.** `~/.config/opencode/opencode.jsonc` is stored encrypted as
  `opencode.jsonc.sops.yaml`. Use `mise run decrypt:opencode` and
  `mise run encrypt:opencode`; never commit the plaintext.

### New files are invisible

This repo sets `status.showUntrackedFiles = no`, because `$HOME` is full of
untracked noise. A file you just created shows up in **neither** `yadm status`
nor `yadm diff`. Nothing is wrong — it simply is not reported.

So a clean `yadm status` never means "nothing to commit". Stage new files by
explicit path:

```bash
yadm add path/to/new-file
yadm status --short --untracked-files=normal   # only if you must browse untracked
```

## Workflow

```bash
yadm status                 # what changed
yadm diff                   # inspect unstaged changes
yadm diff --stat            # summary
yadm log --oneline -20      # study past commit-message style before writing one
```

Commit and push:

```bash
yadm add <paths>            # stage specific files (avoid blanket `yadm add -u` unless asked)
yadm commit -m "<emoji> <scope>: <summary>"
yadm push
```

- Prefer staging explicit paths over everything, so unrelated pending changes are
  not swept into the commit.
- If several unrelated changes are pending, ask whether to split them into
  separate commits.

## Gitmoji quick reference

| emoji | when |
| ------- | ------ |
| ✨ | new feature / add config or tool |
| 🔧 | tweak / change existing config |
| 🐛 | fix a bug |
| ♻️ | refactor without behavior change |
| 🗑️ | remove files or config |
| 📝 | docs / comments |
| ⬆️ / ⬇️ | bump deps up / down |
| 🎨 | formatting / structure only |

Pick the emoji that matches the dominant change. Full list: <https://gitmoji.dev>
